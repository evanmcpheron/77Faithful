# 03 · V1 Scope

[Documentation guide](README.md)

**Authority:** This document owns what is included in the first release. Detailed behavior is defined in the linked subject documents.

## Definition of V1

V1 is a complete, private, personal 77-day formation experience. It must work from a person's first introduction through the end of a journey and the review of previous journeys. It is not merely a set of sample screens, a checklist without Scripture, or a partial course that runs out of content.

The scope below is a product commitment, not a statement of current implementation status.

## Scripture availability is a release condition, not a hidden scope substitution

The intended translation catalog is listed in Document 06. Every translation actually offered must have an approved basis for its use and support the reading experience promised to participants.

The desired list is not a claim of permission. An unavailable translation cannot appear as a working option. A narrower launch catalog requires an explicit, documented product-owner release decision; it must not be silently substituted while claiming the full catalog was delivered. At least one approved translation and all 77 assigned readings must be available before any participant journey is offered.

The full daily content must be written and reviewed before release. An editorial outline or an example devotional does not satisfy this requirement.

## Explicitly not V1

| Capability | Status and boundary |
| --- | --- |
| Private communities | **Future — committed direction.** No community creation, invitations, group progress, shared prayer requests, or discussions in V1. |
| Group-led journeys | **Future — committed direction.** A later shared schedule must preserve private personal records. |
| Scheduled future start | **Future — possible.** V1 starts immediately when confirmed. |
| Multiple content tracks or varied repeat journeys | **Future — possible.** V1 has one fixed course, not a daily reading marketplace or randomized selection. |
| Donation button | **Future — possible.** Any support must be voluntary, unobtrusive, and unrelated to access or spiritual status. |
| Journal text search | **Future — possible.** V1 has chronological browsing and a journey filter, not full-text search. |
| Bookmarks and favorites | **Future — possible.** No separate saved-passages, favorite-days, or favorite-reflections collection in V1. |
| Personal export or printable journey book | **Future — possible.** Personal writing remains viewable in V1; a dedicated download/export experience is not promised. |
| Dedicated prayer journal | **Future — possible.** V1 provides a prayer prompt and completion marker, not a separate prayer-entry or answered-prayer system. |
| Audio recordings, full Bible browsing, study tools | **Future — possible.** Accessible reading is required; a built-in audio Bible, commentary library, passage search, highlighting, and note system are not. |
| Translated app experiences | **Future — possible.** The initial content and interface are in English. A list of English Bible translations is not multilingual app support. |
| Child profiles and parent-managed accounts | **Outside V1.** Families may participate alongside one another, but V1 does not manage children's independent journals under a parent account. |
| Photo, video, or voice journal attachments | **Outside V1.** Private writing is text only. |
| Profile pictures and detailed biographies | **Outside V1.** The personal experience does not require them. |
| Standalone private messages or live chat | **Outside V1 and not a committed future requirement.** Future communities are not permission to add unrestricted messaging. |

## Prohibited in every version

Paid access, advertising, sponsored placements, paid translation tiers, paid community tools, competitive rankings, spiritual scores, badges, achievement awards, public popularity metrics, coerced sharing, and automatic exposure of private writing are not deferred features. They conflict with the permanent product principles.

Custom user-created practices are also not part of the defined product. Any later proposal to add them would require an explicit product change, not interpretation of the existing two-choice customization rule.

## Complete does not mean complex

The first release should provide a dependable and coherent personal experience. It does not need a full social network, an extensive Bible-study suite, a content marketplace, or elaborate progress analytics to fulfill the mission.

A small feature is still required when it protects a central promise—for example, a clear warning before deleting private writing. A large feature is not justified merely because a future community might eventually use it.

## Decisions that still require real-world confirmation

Scripture-use permissions, the final released translation catalog, editorial approval of the 77-day course, participant eligibility and safeguarding policies, the actual support contact, and truthful account-deletion disclosures must be settled before the relevant experience launches.

These are release conditions, not permission to invent credentials, publish placeholders, make unsupported availability claims, or quietly remove core behavior. See [Editorial and launch checklist](19-editorial-and-launch-checklist.md).
